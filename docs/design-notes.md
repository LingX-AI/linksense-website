# Design adaptation

The `bit` preview takes its structural direction from the public [React Bits homepage](https://reactbits.dev/), inspected at 1280 × 720 on November 23, 2026: a full-bleed masthead, a compact left-aligned introduction, and an expansive framed workbench with an editor, stacked utility panels, and animated waves. LinkSense keeps its own brand, Inter typeface, product media, claims, localization, and routes. This is a new structure, not a recolour of the earlier split hero and marketing-card template.

| Area | LinkSense adaptation |
| --- | --- |
| Masthead | A sticky, full-bleed bar with a hairline rule replaces the floating rounded pill. The wordmark is followed by a small slash-separated navigation group; GitHub, the theme control, and one prominent demo action sit on the right. The mobile sheet keeps every route, document link, GitHub, demo, and language choice. |
| Home introduction | The open-source chip, two-line headline, and both real actions are left-aligned. The short product explanation and self-hosting link sit low on the right, as in the reference. The headline is intentionally smaller than the former display hero so the workbench, not the introduction, carries the page. |
| Workbench | A single large frame dominates the first viewport. The editor side reserves the real capture footprint with a localized prompt for a completed supplier comparison, with the workspace demo link beneath it. The right stack contains a task inspector, the example deliverables (each linked to its use-case anchor), and three starting presets. [Gradient Waves](https://reactbits.dev/backgrounds/gradient-waves) animates only behind that utility stack. The initial HTML contains no autoplay recording, and the full demo opens on request. |
| Library | Below the workbench, the homepage becomes a working index rather than a sequence of equal marketing cards: an asymmetric two-item capability library with localized prompts for focused Skill and connector-detail captures, a compact use-case catalogue with anchors, a film utility panel, and a self-hosting/governance panel with the real Core and Full deployment links. |
| Detail introductions | Both detail routes use the same compact page lead: a source or example-data chip, a display headline, supporting copy, and one useful action. The use-cases chip jumps to the catalogue; the self-hosted chip opens the GitHub source. |
| Use cases | The page is a static catalogue and inspector. A sticky numbered index sits beside three entries. Each entry pairs readable task copy with a distinct artifact: the document preview for procurement, a brief outline for reporting, and a question, answer, and citation block for knowledge. All entries remain in the SSR HTML and are reachable by hash. Capability sharing reserves the former media footprint with a localized prompt for real app-sharing settings. |
| Self-hosted | The page reads as compact technical documentation. A sticky “On this page” rail links the stable `#profiles`, `#governance`, and `#boundaries` anchors. Core and Full are separate deployment profiles with distinct roles, platform requirements, and real deployment-guide links. Governance reuses the deployment diagram and access/oversight list; the data-boundary note keeps the security-policy link. |
| Header and theme | The full-bleed header has no floating container. The scheme follows the system by default; the 44px toggle persists an explicit local override and follows system changes until an override exists. Older browsers without `light-dark()` retain the light presentation. |
| Motion and dialogs | Movement is limited to short entry and hover feedback. The waves pause control only appears when a canvas exists and motion is allowed; reduced motion hides the canvas and keeps the static violet CSS background. Native `<dialog>` elements handle the mobile sheet and film, with `overscroll-behavior` on the modal and backdrop, no root scroll lock, and native focus return. With JavaScript unavailable, all page content, anchors, and footer navigation remain in the served HTML. |

## Media

- The header/footer lockups and the app icon come from the LinkSense logo Figma file (`Linksense-logo设计`, node 80:2) and are kept as `public/brand/linksense-lockup-light.svg`, `linksense-lockup-dark.svg` and `linksense-icon.svg`. See the [brand policy](../../linksense/TRADEMARK.md).
- The introduction film is reused from the [existing website's first-party media](../../linksense-site/public/media/README.md). The workspace demo (`product-demo.mp4`) is a code-built motion reconstruction traced from real workspace captures (source project: `~/c/linksense-motion`) and remains available from the workbench with its existing poster and no autoplay. Earlier reconstructed Skill-directory, connector-directory, and sharing media remain on disk for legacy URLs but are not rendered by the current pages. The demo's score is generated, quiet electronic; no spoken dialogue.
- The introduction film has English on-screen text. Its music is **Sonor #2**, Eugenio Mininni, under the [Mixkit Stock Music Free License](https://mixkit.co/license/modal/musicFree/).
- The workbench uses the existing vendored GradientWaves canvas from the React Bits registry, recolored for LinkSense. It is kept as JavaScript with a local type declaration; the shader itself is not type-checked. No React Bits marketing assets are shipped.
- Deliverable illustrations use example data. The blue signal artwork (`signal.webp`) and the two square menu artworks are not referenced by the current pages.
- The bundled Inter font includes its [OFL license](../public/fonts/Inter-LICENSE.txt).
